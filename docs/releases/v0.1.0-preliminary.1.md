# FlahaGrow v0.1.0-preliminary.1

Released 2026-09-11. This is a preliminary milestone, not a scientific-validation or full Rhino-host acceptance release.

## Included

- Manifest-owned annual daylight workflows with stage reporting, validated caches, persisted process identity, cancellation safeguards, and disk/intermediate safeguards.
- Electric Annual Simulation and Combine Annual Lighting source workflows, including a real one-sensor Radiance fixture for electric output.
- Per-component revision/version/update-time tracking persisted in Grasshopper definitions.
- Legacy-compatible `DLI Hourly` and `DLI Each Sensor` components. `DLI Hourly` validates and reads its 24-hour block once per solve rather than revalidating the cache per sensor.
- Annual Plot and Annual Plot PPFD for Sensor accept 8,760 hourly, 365 daily, and 12 monthly annual series without a port migration.
- Spectrum custom-CSV/table implementation is included, but parity and real Rhino UI acceptance remain explicitly open.

## Validation performed

- `dotnet build FlahaGrow.sln --configuration Release --no-restore -m:1`: passed with zero warnings and errors.
- `tools/Test-SetupComponents.ps1 -NoRestore`: passed; 43 revision-tracked components and annual/cache integration checks passed.
- `dotnet test tests/FlahaGrow.Core.Tests/FlahaGrow.Core.Tests.csproj --configuration Release --no-restore -m:1`: 168/168 passed.
- Installed release build at the time of the milestone: `FlahaGrow.gha` SHA-256 `D309954B82EB53F875EE268A3F1079B157DA213C6761802450C8DF10928193F3`.

## Known release boundaries

- Rhino-host acceptance is still required for selector persistence, save/reopen, Timer refresh, cross-session cancellation, the DLI sensor-point tree/marker, and the spectrum table UI.
- Annual daylight has a recorded successful 980-sensor, 8,760-hour Rhino run; broader numerical/reference-scene validation remains required before scientific or design decisions.
- Electric Annual and Combine Annual Lighting require real exported-luminaire/Rhino acceptance.
- Spectral custom-CSV results require locked reference parity testing against the legacy workflow.
